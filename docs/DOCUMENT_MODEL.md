# Media and composition document

Schema 2, 2026-10-03. The Rust document, typed commands, CLI, MCP, native tabs and
recovery share this representation. This layer evaluates frame plans. The native
codec/GPU feasibility tools remain separate until the production engine consumes
those plans; a plan is not a picture, sound block or completed production job.

## Identity and migration

Project, sequence, asset, source, composition, track, clip, node and animation
channel IDs are nonempty and globally unique within a document. Revisions advance
once per accepted group and continue advancing through undo/redo. A recovered
project receives an independent project ID and retains its origin; interior IDs
retain editable relationships.

Schema 1 upgrades in memory without changing identity, revision, names or profiles.
Opening it does not write its source. A manual checked save writes the current
schema; `editbay migrate SOURCE NEW_FILE` creates a separate format copy without
overwriting either destination. Future/unknown schemas fail. Schema 1 cannot carry
new media/composition fields. Immutable legacy checkpoints retain their original
canonical serialization: integrity is verified before migration. The pinned old
checkpoint was written by the R1 CLI, not generated by the new migrator.

## Assets, streams and time

Assets retain kind, local path, expected byte hash/size and provenance. The core
validates reference structure; it does not read or certify the referenced media.
Production ingest and worker preflight must verify actual bytes. Missing assets
can remain in editable project data. Font/title/LUT/mask references do not execute
scripts or open files through document commands.

Media sources name their asset and explicit stream indices. Streams retain codec,
seconds-per-tick rational time base, signed presentation origin, optional duration,
source color tags and metadata such as reel/timecode. Video keeps dimensions,
sample aspect, alpha convention and either an explicit CFR rate or an ordered VFR
presentation table with an exclusive end. Audio keeps native sample rate and named
channel order. An average frame rate never replaces a declared VFR table.

Sequence/composition placement uses integer frame boundaries. Each clip has an
exclusive-end frame range and a piecewise linear mapping from clip-local frame
boundaries to source ticks. Points start at zero and end at clip duration. Exact
fractions retain forward, reverse, freeze and nonuniform speed; overflow fails
visibly. A nested source uses the child's frames as source ticks. Frame selection
and sample conversion happen after mapping. Reverse selection uses the picture
immediately before its boundary, so starting at a source's exclusive end selects
the last picture. Freeze cannot hold an exclusive source end.

Tracks have explicit video/audio types and enabled state. Linked clips are
reciprocal pairs within one composition. Sources and nested outputs must match
the track type. Sequence and attached composition profiles must agree.

## Graph and animation

The implemented document operations describe source, linear working-space solid,
transform, image-over-image with optional mask, polygon geometry, feathered/inverted
mask, mask asset, audio gain/mix, scalar data and scalar-controlled image opacity.
Sockets distinguish image, mask, geometry, audio and data. Missing inputs, wrong
socket/output types, duplicate properties and graph/nesting cycles fail before a
command publishes. Traversal uses work queues rather than recursive graph walks.

Timed nodes use composition frames and exclusive ends. Channels address supported
parameters directly; keys are ordered and finite. Step, linear and cubic Hermite
evaluation hold endpoints. Hermite slopes use value change per frame; evaluated
alpha/opacity clamp to 0..1 and gain/feather remain nonnegative. Polygon coordinates,
translation and feather use composition pixels; rotation uses degrees. Solids use
straight linear RGBA; source alpha interpretation remains explicit.

Working gamut/float precision, display gamut/transfer and output gamut/transfer are
separate typed settings. Storing those settings does not qualify an OCIO/HDR/display
transform; the production renderer and independent color gates remain required.

`Project::frame_plan` returns deterministic input-first reachable nodes, resolved
animation, exact source requests, picture/sample ordinals and current ownership.
Inactive nodes retain their socket with no active source request; the consuming
engine must supply transparent image/mask, empty geometry, zero scalar or silence.
Nested requests preserve exact fractional child position and reverse direction.
The frame-plan API does not round those child positions into a rendered frame.

Composition fingerprints include the transitive semantic graph, source byte hashes
and interpretation, masks, animation and color. Labels, project revision, unrelated
scenes and reel/timecode metadata do not affect them. Frame fingerprints also include
time and evaluated nodes. Workers must still reject obsolete document ownership;
reusable immutable content and permission to publish are separate checks.

## Commands and limits

`rename_project`, `set_sequence`, `remove_sequence`, `set_asset`, `remove_asset`,
`set_source`, `remove_source`, `set_composition`, `remove_composition` and `set_color`
are implemented core commands. Set replaces an existing identity or appends a new
one; removal refuses absent or still-required data. A group contains 1..64 commands
in dependency order. Every intermediate state validates. Build assets, sources,
child scenes, parent scenes and sequence references in that order; detach parents
before removing their dependencies. A failed group changes neither data nor history.

Undo retains changed entities and collection positions, with at most 128 groups and
16 MiB serialized delta data. Larger groups fail before mutation. Immutable `Arc`
snapshots let UI frames and filesystem jobs retain a version without cloning its
graph. Saved-tab dirty checks use command ownership; file workers construct loaded
editors and perform serialization. History remains local to a session.

Core project/recovery reads and serialization have a 64 MiB limit. Native catalog
and open currently use an explicit 8 MiB limit; CLI command requests also use 8 MiB.
Validation permits at most 100,000 document identities, 256 tracks/streams per owner,
32,768 nodes per composition, 65,536 time-map/polygon points and one million animation
keys per composition. Metadata has 128 entries with bounded text; audio has at most
64 named channels. Media/composition pictures have dimensions 1..16,384; legacy
empty sequence profiles retain their original positive-dimension contract. These
are document limits, not decode/playback performance claims.

```sh
editbay apply JOB.editbay COMMAND_GROUP.json
editbay frame-plan JOB.editbay COMPOSITION_UUID 24
editbay migrate LEGACY.editbay NEW_SCHEMA2.editbay
```

The JSON request is the same `CommandGroup` used by MCP: `expected`, `label` and
`commands`. `inspect_frame_plan` additionally requires current document ownership.
References remain inert data within the opened project; source reading, preview,
export and source permissions are not widened by these commands.
