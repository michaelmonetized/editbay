# Captions, color and multicam

The native document view now contains Captions, Color workspace and Multicam. The same document commands drive authoring, undo, recovery, CLI automation and delivery. Older schema-2 projects default these retained collections to empty; no version bump or schema migration is required.

Captions import and export UTF-8 SRT/WebVTT with exact rational native cue timing. Add, edit, split at the program playhead, retime, select safe margins and retain a font. Track delivery chooses preview, SRT/VTT sidecars, burn-in or both. Sidecars are clipped and rebased to an export range and published beside the verified master. Existing destinations are refused. Standard subtitle files cannot represent submillisecond boundaries: export rejects that loss instead of rounding. VTT identifiers, settings, comments and STYLE/REGION blocks survive interchange; unsupported rich caption burn-in fails visibly. Burn-in uses shaped Unicode glyphs from a fingerprinted retained font; missing glyphs fail. Preview safe guides use the same retained margins. Choose a retained font to preview text: sidecar and preview-only tracks then use the same Unicode shaping, colors and layout as burn-in on the viewer worker, after program scopes are measured.

`editbay captions-import FILE COMPOSITION_ID SOURCE_SRT_OR_VTT` and `editbay captions-export FILE TRACK_ID NEW_SRT_OR_VTT` expose the shared import/export path. Shared `set_caption_track` commands retain exact edits and undo.

Color workspace has waveform, RGB parade and vectorscope. Enable Live scopes to capture the actual program's premultiplied linear float picture on its existing render worker. Reports carry document revision, composition and displayed frame; stale owners and previous settings are not accepted. Linear/nits plots preserve the working gamut and overrange/negative values. Nits depend on the explicitly selected reference-white scale. Output-code plots convert to the declared output primaries/transfer, including analytical PQ/HLG values. This does not add HDR display/output support to the renderer. Counts describe bounded deterministic samples; labels show units and sample limits. Readback happens off the UI thread and only when scopes are enabled. Native playback performance is not qualified by the numeric tests.

Multicam retains original camera compositions, exact rational sync offsets, angle cuts and fixed/follow/all audio policy. Create a session from two or more camera compositions, synchronize source markers or start timecodes, or measure actual decoded audio envelopes. The native audio helper uses 200 Hz envelopes from original 48 kHz PCM, a bounded search and explicit confidence rejection. Its 5 ms lag grid remains rational when converted to video frames. The underlying correlation API also accepts higher-rate bounded arrays. Silent/ambiguous material fails sync visibly; it never invents a successful match. Matching dimensions are required; mixed frame rates map exactly, and different dimensions need explicit conform first.

The angle grid shows exact source positions and offers native source/program viewing. Cut adds a boundary at the playhead; switch changes the owning segment while keeping its boundaries. Both rebuild the existing native picture/sound graph through `set_multicam_session`. Saving/reopening retains the exact edit. Export uses that compiled native graph, with the existing supervised encode/decode QC path. Grid thumbnails and live performance are not claimed from source/headless tests.

Focused software tests cover known color ramps/HDR constants, Unicode cue formats, save/reopen/recovery, stale commands, sync lags/timecode/drop-frame, source positions at cuts and audio policies. No desktop, sound-device, hardware, installation or release qualification was run for this stream.
