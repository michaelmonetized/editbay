# Retained multicam edits

Multicam retains original camera compositions, exact rational sync offsets, angle cuts and fixed/follow/all audio policy. Create a session from two or more camera compositions, synchronize source markers or start timecodes, or measure actual decoded audio envelopes. The native audio helper uses 200 Hz envelopes from original 48 kHz PCM, a bounded search and explicit confidence rejection. Its 5 ms lag grid remains rational when converted to video frames. The underlying correlation API also accepts higher-rate bounded arrays. Silent/ambiguous material fails sync visibly; it never invents a successful match. Matching dimensions are required; mixed frame rates map exactly, and different dimensions need explicit conform first.

The angle grid shows exact source positions and offers native source/program viewing. Cut adds a boundary at the playhead; switch changes the owning segment while keeping its boundaries. Both rebuild the existing native picture/sound graph through `set_multicam_session`. Saving/reopening retains the exact edit. Export uses that compiled native graph, with the existing supervised encode/decode QC path. Grid thumbnails and live performance are not claimed from source/headless tests.

Source positions, audio policies, synchronization, stale commands, undo and save/reopen have focused software checks. Committed angle edits pause the existing viewer on its document-revision boundary; continuous live recording and native rendered delivery are separate qualification boundaries. No desktop, sound-device or hardware tests are claimed.
